# Portfolio page rewrite

Today I worked on a total back-end rewrite of the portfolio page in an attempt to make the page itself less bloated and remove the hard coded nature of it. This should result in a page that is lighter and loads faster. 

Basically, you can use the github api to request data during runtime. So I now have a folder in my website repo that got all the artpieces I want to display on the portfolio page. Then by using some javascript it looks for the art folder, takes the images from there, and displays them dynamically on the webpage.

To make sure you don't hit any rate limits (Github has a rate limit of 60 requests per hour per IP), I use the API for your first visit, and store everything in the local storage of your browser. So when you visit the page multiple times, it'll display your local storage first, making the page load faster, makes sure you don't hit any rate limits, and makes the page more responsive. This local storage data is stored for 60 minutes. After said 60 minutes the page will check for new data and update if necessary. Run into a rate limit? No worries, the local storage will be used instead!

This rewrite also includes a system that automatically names each image based on the file name, which also has another system that removes anything that I put between brackets. After that, every item is ordered in a reverse alphabetic order. 

So for example: `[Ch6S4-1]Fox-Clan-Drip.webp` becomes `Fox Clan Drip`. And higher numbers in the chapter part of the file name appear higher in the list, so newer chapters will be higher in the list compared to older chapters. Newer artpieces are on the top while my older work is on the bottom. This will better reflect my growth as an artist as you can really see how my art improved over time.
